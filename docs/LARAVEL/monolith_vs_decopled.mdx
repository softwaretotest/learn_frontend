# monolith vs decoupled

## 📊 Monolith VS Decoupled Architecture

A quick code and command comparison between Monolith and Decoupled (Separate API) setups.

| Feature / Topic        | 📦 1. Monolith (All-in-One)                                                                                       | 🌐 2. Decoupled (Separate API)                                                                                      |
| :--------------------- | :---------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------ |
| **Concept**            | Laravel and React live in one project.                                                                            | Two standalone projects (Backend & Frontend).                                                                       |
| **Folder Structure**   | **One Root Folder**<br />├── `app/` (Backend)<br />├── `resources/js/` (React)<br />└── `composer.json` (At root) | **Two Separate Folders / Repos**<br />├── **backend/** (Laravel API only)<br />└── **frontend/** (React App only)   |
| **Local Run Commands** | **Run in 1 Root Folder:**<br />• Terminal 1: `npm run dev`<br />• Terminal 2: `php artisan serve`                 | **Run in Separate Folders:**<br />• Inside `/frontend`: `npm run dev`<br />• Inside `/backend`: `php artisan serve` |
| **CORS Configuration** | **No setup needed.**<br />Both run on the same port and domain.                                                   | **Required.**<br />Must configure `config/cors.php` in Laravel.                                                     |
| **API Code Example**   | **Direct endpoint:**<br />`axios.get('/api/products')`                                                            | **Absolute URL endpoint:**<br />`axios.get('https://myshop.com')`                                                   |
| **Database Security**  | Eloquent ORM and `.env` credentials stay 100% on the server side.                                                 | Eloquent ORM stays hidden inside the isolated backend server.                                                       |
| **Validation Setup**   | Frontend validates forms. Laravel catches data and runs `\$request->validate()`.                                  | Frontend validates, sends JSON to backend, backend re-validates and returns error responses.                        |
| **Render Deployment**  | **1 Web Service (Cheapest)**<br />• Language: Native PHP<br />• No Docker files required.                         | **2 Services OR 1 Service with Docker**<br />• Requires complex multi-stage `Dockerfile`.                           |
| **Best For**           | **Solo Developers / E-commerce Owners**<br />Fast development and lowest hosting cost.                            | Large teams with separate Frontend and Backend engineers.                                                           |

ตารางเปรียบเทียบโครงสร้างและการทำงานระหว่างการรวมโค้ดไว้ที่เดียว (Monolith) กับการแยกฝั่งหน้าบ้าน-หลังบ้าน (Decoupled) เพื่อประกอบการตัดสินใจสำหรับโปรเจกต์ E-commerce

| คุณสมบัติ / หัวข้อ                                | 📦 1. แบบรวมศูนย์ (Monolith Architecture)                                                                                                                                                                        | 🌐 2. แบบแยกฝั่งเด็ดขาด (Decoupled / Separate API)                                                                                                          |
| :------------------------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **แนวคิดหลัก <br />(Concept)**                    | รวม Laravel และ React ไว้ในโปรเจกต์เดียวกัน โดยให้ Laravel เป็นหลัก และฝัง React ไว้ในโฟลเดอร์ของระบบหน้าบ้าน                                                                                                    | แยกโปรเจกต์ออกจากกันเป็น 2 ก้อนอิสระ (Laravel ทำหน้าที่เป็น API Server เท่านั้น ส่วน React แยกตัวเป็น App อีกตัว)                                           |
| **โครงสร้างโฟลเดอร์ <br />(Structure)**           | **มีโฟลเดอร์นอกสุดตัวเดียว (Root)**<br />├── `app/Models/` (Eloquent ORM)<br />├── `resources/js/` (ที่อยู่ของ React ทั้งหมด)<br />├── `routes/api.php` (ท่อส่งข้อมูล)<br />└── `composer.json` (อยู่ด้านนอกสุด) | **แยกเป็น 2 โฟลเดอร์ใหญ่ (หรือแยก 2 Repository)**<br />├── **backend/** (มีเฉพาะโค้ด Laravel API)<br />└── **frontend/** (มีเฉพาะโค้ด React + package.json) |
| **การไหลของข้อมูล <br />(Data Flow)**             | บราวเซอร์เรียก URL เดียว -> Laravel ส่งหน้าจอ React ไปให้ -> พอจะดึงข้อมูล React ยิงหา `/api/...` ในโดเมนตัวเอง                                                                                                  | บราวเซอร์เรียกเว็บ React -> React ยิง HTTP Request (Axios) ข้ามเน็ตเวิร์กไปหาเซิร์ฟเวอร์ Laravel API เพื่อขอ JSON                                           |
| **ความปลอดภัยของ DB <br />(Database Security)**   | **ปลอดภัยสูงมาก:** โค้ด Eloquent ORM และไฟล์รหัสผ่านฐานข้อมูล (`.env`) ถูกกักไว้และประมวลผลบนเซิร์ฟเวอร์เท่านั้น บราวเซอร์ลูกค้าเห็นแค่ UI ของ React                                                             | **ปลอดภัยสูงมากเช่นกัน:** โค้ด Eloquent ORM อยู่ในเซิร์ฟเวอร์หลังบ้านแยกตัวต่างหาก ลูกค้าเห็นแค่โค้ดหน้าบ้านที่คอมไพล์แล้วเช่นกัน                           |
| **การตรวจสอบข้อมูล <br />(Validation)**           | **ทำคู่กันได้ง่าย:** หน้าบ้านตรวจฟอร์มเบื้องต้น (เช่น ห้ามว่าง) และหลังบ้านตรวจด้วย Laravel Validation อีกชั้นก่อนลงฐานข้อมูล                                                                                    | **ทำคู่กันแต่ซับซ้อนกว่า:** ตรวจหน้าบ้านเสร็จ ต้องยิง API ไปให้หลังบ้านตรวจซ้ำ และต้องเขียนโค้ดแปลง Error JSON กลับมาโชว์หน้าบ้านเอง                        |
| **ปัญหาเรื่อง CORS <br />(Cross-Origin)**         | **ไม่มีปัญหานี้เลย:** เนื่องจากทั้ง React และ Laravel รันอยู่บนโดเมนและพอร์ตเดียวกัน (เช่น `myshop.com`)                                                                                                         | **มีปัญหาและต้องตั้งค่าเพิ่ม:** ต้องไปเปิดสิทธิ์ใน `config/cors.php` ของ Laravel เพื่ออนุญาตให้โดเมนของ React ยิงเข้ามาได้                                  |
| **การรันบนเครื่อง <br />(Local Running)**         | **ง่ายมาก:** รันคำสั่งเปิดเซิร์ฟเวอร์ปกติ ไม่จำเป็นต้องติดตั้งหรือเรียนรู้ระบบ Docker บนเครื่องคอมพิวเตอร์ของคุณเลย                                                                                              | **ปานกลาง:** ต้องเปิด Terminal แยก 2 หน้าต่างเพื่อรันเซิร์ฟเวอร์ PHP และเซิร์ฟเวอร์ Node.js พร้อมกันเพื่อให้คุยกันได้                                       |
| **การดีพพลอยบน Render <br />(Render Deployment)** | **ง่ายและประหยัดที่สุด:** Render ตรวจเจอ `composer.json` ทันที รันเป็น PHP Native ได้ **จ่ายเงินค่าโฮสต์แค่ 1 Web Service**                                                                                      | **ยุ่งยากกว่าหรือจ่ายแพงกว่า:** ต้องแยกดีพพลอยเป็น 2 เซิร์ฟเวอร์ (จ่ายเงิน 2 ต่อ) หรือถ้าจะรวมที่เดียวต้องเขียน Dockerfile ผสมระบบ                          |
| **ความเหมาะสม <br />(Suitability)**               | **เหมาะมากสำหรับ Solo Developer** ที่ทำระบบ E-commerce คนเดียว ต้องการความเร็ว ทำง่าย ปลอดภัย และประหยัดค่าโฮสต์                                                                                                 | เหมาะสำหรับทีมที่มีผู้พัฒนาหลายคน (เช่น แยกทีมทำเฉพาะ Frontend และทีมทำเฉพาะ Backend) หรือทำแอปมือถือควบคู่ไปด้วย                                           |
